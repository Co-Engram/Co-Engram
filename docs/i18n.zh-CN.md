# 国际化(中文 / English)

Co-Engram 开箱即支持**中英双语**。工具描述、查看器 UI 以及注入的系统提示词均已本地化。中文团队与英文团队可以使用同一个记忆仓库,并各自选用偏好的语言。

## 工作原理

```
┌─────────────────────────────────────────────────────────────┐
│ 语言解析优先级(从高到低):                                    │
│                                                             │
│   1. 运行时覆盖                                              │
│      - MCP: CO_ENGRAM_LANGUAGE=zh                           │
│      - OpenClaw: plugins.entries.co-engram.config.language  │
│                                                             │
│   2. 持久化的 team-memory 选择                               │
│      - ~/team-memory/.co-engram/config.json                 │
│      - 由 `co-engram init` 写入                             │
│                                                             │
│   3. 默认: zh(中文,本项目主要面向中文团队)                    │
│      国际团队可设置 CO_ENGRAM_LANGUAGE=en 或在 config.json   │
│      中设 language: 'en'。                                   │
└─────────────────────────────────────────────────────────────┘
```

自 0.2.0 起,默认语言为**中文(`zh`)**。本项目主要为中文团队构建,默认 zh 让查看器 UI、工具描述、系统提示词在无需配置的情况下都是中文。国际团队通过设置 `CO_ENGRAM_LANGUAGE=en` 或在 config.json 中设置 `language: 'en'` 来切换为英文。

## 首次使用时选择语言

推荐方式:使用 `co-engram init`。

```bash
co-engram init
# → Where should team-memory live? [default: ~/team-memory]
# → Choose language:
#     1. English (recommended for international teams)
#     2. 简体中文 (recommended for Chinese teams)
# → Default creator? [default: $USER]
```

该选择会被持久化到 `~/team-memory/.co-engram/config.json`:

```json
{
  "version": 1,
  "language": "zh",
  "defaultCreatedBy": "alice",
  "createdAt": "2026-06-21T...",
  "initializedBy": "co-engram-cli@0.1.0"
}
```

Claude Code(MCP)和 OpenClaw(插件)都会自动读取此文件。

## 运行时覆盖

你不必永久锁定某一种语言。可以按会话覆盖:

### Claude Code(MCP)

```bash
claude mcp add co-engram \
  -e CO_ENGRAM_DATA_ROOT=$HOME/team-memory \
  -e CO_ENGRAM_LANGUAGE=zh \
  --scope user \
  -- co-engram-mcp
```

或针对单次运行临时设置:

```bash
CO_ENGRAM_LANGUAGE=en co-engram-mcp
```

### OpenClaw(插件 manifest)

在你的 OpenClaw 配置中(例如 `~/.openclaw/config.yaml`):

```yaml
plugins:
  entries:
    co-engram:
      enabled: true
      config:
        dataRoot: /home/your/team-memory
        language: zh
```

## 被翻译的内容

| 表面                             | 示例                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 工具描述(28 个工具,LLM 友好格式) | `engram_create` — "Create a new memory (engram) for important team knowledge. **WHEN TO CALL:** ..." / "为重要的团队知识创建新记忆(engram)。**何时调用:** ..."    |
| 工具描述(回退版,面向开发者)      | 尚未进入 LLM 字典的工具会回退到 core i18n 字符串(例如 `engram_archive` — "Archive an engram (move out of default retrieval, but data preserved and recoverable)") |
| 查看器 UI                        | "Co-Engram Viewer" / "Co-Engram 查看器";按钮、标签页、加载提示等                                                                                                  |
| 系统提示词注入                   | "3 memory candidates pending" / "3 个候选记忆待处理"                                                                                                              |
| CLI 提示                         | `co-engram init` 的欢迎语、语言选择器、下一步提示                                                                                                                 |

### 双层工具描述

Co-Engram 分两层解析工具描述,**两种宿主共用**:

1. **`LLM_TOOL_DESCRIPTIONS`**(位于 `@co-engram/core`)—— 为全部 17 个 standard-profile 工具(含仓库健康工具 `engram_doctor`、`engram_list_paths` 与 LLM 综合 `engram_synthesize`)提供的结构化 "WHEN TO CALL / WHEN NOT TO CALL / RETURNS" 描述。这是 LLM 在最常用工具上默认看到的内容。
2. **Core i18n 字典**(`tool.*` 键)—— 面向开发者的较短描述,服务于无需完整 LLM 化的内部/管理类工具(`engram_archive`、`skill_invoke` 等)。

MCP server 和 OpenClaw 插件适配器都通过同一个 `resolveLlmDescription()` 辅助函数解析,因此 Claude Code 用户与 OpenClaw 用户在同一工具上看到的是一致的描述。

## 不翻译的内容

- **工具名** —— 始终为 snake_case 英文(`engram_create`、`synapse_list`)。LLM 工具调用 API 期望稳定标识符;翻译名称会破坏 agent 集成。
- **文件布局** —— `<domainTags>/<slug>.md`、`synapses/<kind>/syn-<hash>.yaml` 等始终为英文,以便对 Git 友好。
- **枚举值** —— `kind: fact` 保持为 `fact`(不写成 `类型: 事实`),`status: active` 保持为 `active`,`extends` 保持为 `extends`。这些值是 TypeScript 字面量 union 类型,在约 25 个消费者中用 `===` 比较;翻译会破坏类型系统。YAML 键会本地化(`类型:`、`状态:`、`类型: extends`),但枚举值保持英文。
- **运行时对象的字段名** —— Co-Engram 解析文件后,内存对象始终用英文键(`{ id, title, kind, createdAt, ... }`),与磁盘格式无关。中文 YAML 键只存在于磁盘上便于人类阅读;解析时归一化回英文。这意味着 25 个消费者模块都不需要感知磁盘语言。
- **core 引擎的错误消息** —— 运行时错误保持英文(面向开发者,而非用户)。
- **engram 内容本身** —— 你写下的实际记忆就是你书写时所用的语言。Co-Engram 不会翻译你的数据。

## 磁盘格式 vs 运行时格式

Co-Engram 区分**磁盘格式**(人类用编辑器打开文件看到的内容)和**运行时格式**(代码解析后看到的对象)。

**英文模式(`language='en'`)**下,两者都是英文:

```markdown
---
id: 01J...
title: Some fact
kind: fact
createdAt: 2026-06-21T...
---

body content
```

**中文模式(`language='zh'`)**下,磁盘翻转为「正文在上 + 中文键 + `__语言: zh` 标记」,但运行时对象与英文模式完全一致:

```markdown
body content

## <!-- co-engram-meta:zh -->

标识: 01J...
标题: Some fact
类型: fact
创建时间: 2026-06-21T...
\_\_语言: zh

---
```

两种格式都解析为同一个 JavaScript 对象 `{ id: '01J...', title: 'Some fact', kind: 'fact', createdAt: '...' }`。中文键纯粹是为了人类阅读的便利。

Host 首次以新的 `language` 启动时会执行 `repository.migrateFormat(language)`,把所有文件重写为目标格式。详见 [data-format.zh-CN.md](./data-format.zh-CN.md) 中 `migratedToLanguage` 的机制说明。

## 新增一种语言

Co-Engram 目前内置 `en` 与 `zh`。新增第三种语言(例如 `ja`)的步骤:

1. 在 [packages/core/src/i18n/types.ts](../packages/core/src/i18n/types.ts) 的 `Language` 类型中加入该语言代码
2. 在 [packages/core/src/i18n/](../packages/core/src/i18n/) 下创建 [packages/core/src/i18n/ja.ts](../packages/core/src/i18n/),镜像 `en.ts` 的键结构
3. 在 [packages/core/src/i18n/index.ts](../packages/core/src/i18n/index.ts) 的 `DICTIONARIES` 中注册
4. 将其加入 `SUPPORTED_LANGUAGES`
5. 更新 `parseLanguage()` 以识别新代码
6. 在 [packages/core/test/i18n.test.ts](../packages/core/test/i18n.test.ts) 中补充测试

字典约有 60 个键(25 个工具描述 + 查看器字符串 + CLI 提示)。完整翻译大约耗时一小时。

## 验证

执行 `co-engram init --language zh` 后:

```bash
# 重启 Claude Code,然后:
/mcp
# 列出的工具 —— 描述应为中文

# 或通过查看器(当 CO_ENGRAM_VIEWER_ENABLED=1 时):
curl http://127.0.0.1:18799/ | grep -o '<html lang="[^"]*"'
# → <html lang="zh">
```

## 设计理念

**为何原生双语,而非通过翻译层?**

- LLM 会逐字看到工具描述。翻译质量不佳会降低工具调用准确性。
- 记忆内容是个人/团队特定的。强制中文团队使用英文会在每次写入时制造摩擦。
- "人机共生"目标要求双方都能舒适地阅读 —— 人类编辑 engram 的 Markdown 正文,AI 调用工具。

更宏观的理念见 [design-rationale.md](./design-rationale.zh-CN.md)。
